The Standard

The unifying principle: write the cheapest test that meaningfully exercises the behavior. A pure function gets a unit test. A function that talks to a database gets an integration test against a real (test) database, not a mocked one. A user-facing flow gets one happy-path E2E test.
Test Pyramid & Testing Trophy
  • Pyramid (Cohn). Many fast unit tests at the bottom, fewer integration tests, very few slow E2E tests on top. The geometry is a cost model: a unit test runs in milliseconds; an E2E test can take minutes.
  • Trophy (Dodds). For modern frontend, lean on integration tests for the highest confidence per dollar, on a base of static analysis (TypeScript, ESLint).
Anatomy of a Good Unit Test
  • Arrange / Act / Assert. One logical assertion per test, so a failure points at one thing.
  • Name the behavior, not the function. test_parser_handles_trailing_comma, not test_parse.
  • Deterministic. No unseeded randomness, no real now() (inject a clock), no real network (inject a transport).
  • Fakes > mocks. Mock external services you don't own (Stripe, SendGrid); don't mock your own database, run a real one in CI.

Build a Real CI Workflow

Pending
Goal: Add a complete .github/workflows/ci.yml to one of my repos with lint, test, a matrix over 2+ versions, dependency caching, and a status badge in the README.
Reference Shape
.github/workflows/ci.yml
name: CI
on:
  push: { branches: [main] }
  pull_request:
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
        node: [20, 22]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: ${{ matrix.node }}, cache: npm }
      - run: npm ci
      - run: npm run lint
      - run: npm test
