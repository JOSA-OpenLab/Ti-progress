Two Well-Formed PRs

Goal: Open two PRs in any public repo using the What / Why / How / Test template and a Conventional Commits title. Small scope is fine — the description must be complete.
PR 1
#22564 docs(ar/echo): add Arabic translation

Repo: tldr-pages/tldr  ·  View PR →

What: Adds pages.ar/common/echo.md — Arabic translation of the echo page.

Why: The Arabic locale is missing ~700 common pages. echo is one of the most fundamental Unix commands, yet it had no Arabic translation.

How: Translated all example descriptions into natural Arabic following the existing style in pages.ar. Avoided word-for-word translation — kept technical terms like terminal and stdin in English.

PR 2
#22565 docs(ar/cp): add Arabic translation

Repo: tldr-pages/tldr  ·  View PR →

What: Adds pages.ar/common/cp.md — Arabic translation of the cp page.

Why: cp is one of the most essential Unix commands for file management, yet it had no Arabic translation in the project.

How: Same approach as PR 1 — natural Arabic phrasing, behavior described instead of flag names (e.g. "مع عرض اسم كل ملف أثناء نسخه" instead of "verbose mode"). Verified against the official translation templates.

Reflection
Before writing a single line, I verified both files didn't exist using a direct GitHub API call — a 404 check, not a keyword search. I read CONTRIBUTING.md and the style guide, compared against recently merged Arabic PRs like docker.md, and used the official translation templates for standard phrases like انظر أيضًا. The main lesson from this task: a maintainer-friendly PR is small, one logical change, and its description answers What/Why/How/Test before anyone has to ask. Keeping technical terms in English (terminal, headers, proxy) instead of forcing formal Arabic translations made the output feel natural rather than machine-generated — and that matters because the maintainers will close PRs that look AI-generated without genuine human review.
