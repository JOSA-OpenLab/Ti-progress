The Standard

The unifying principle: good docs are written from the reader's perspective ("you have a problem, here is what you do"), not the author's ("here is what I built"). For every page, decide which of the four Diátaxis kinds it is and ruthlessly cut anything that belongs to the other three.
Diátaxis, the four kinds of documentation
  • Tutorial. "I want to learn." A teacher walking you through your first success.
  • How-to guide. "I want to solve a specific problem." A recipe for one task.
  • Reference. "I want to look something up." An encyclopedia of the API surface.
  • Explanation. "I want to understand." An essay on the why behind a design.
Google style in 60 seconds
  • Active voice. "The parser reads the file", not "The file is read by the parser".
  • Present tense, second person. "Returns a list." "You can install with pip."
  • Short sentences, sentence-case headings. Two ands or a however means break it up.
  • No "simply", "just", "easy". They are either lies or condescending, the reader is stuck.
Docs as code
  • PR workflow. Doc changes get reviewed like code.
  • CI preview. Every PR builds the site with a preview URL (Cloudflare / Netlify / Vercel Pages).
  • Linting. Style violations fail CI, so a prose linter (Vale) does the nagging, not a human.
  • ADRs. Short, immutable Markdown files in docs/adr/ that record why a decision was made.
Suggested Repositories

mdn/content  ·  github/docs  ·  tldr-pages/tldr  ·  any tool whose README is bad.

Ship One Real Docs PR

Pending
Target: MDN, GitHub Docs, tldr-pages, or a tool with a weak README.
Plan
To do Submit a PR to a major docs project. It can be small, but every line must follow a real style guide: active voice, present tense, second person, sentence-case headings, short sentences, and no simply / just / easy. If I restructure a README, follow Diátaxis order: intro, install, a quick tutorial, then links to deeper docs.
Definition of done
  • One PR opened against a real docs repo, linked here.
  • Every change passes the style checklist (voice, tense, person, headings).
  • The diff is scoped and reviewable, no unrelated edits.

Set Up a Docs Site (MkDocs Material)

Pending
Stack: MkDocs Material, deployed via GitHub Pages or Cloudflare Pages, linked from the repo README.
Plan
To do Pick one of my repos and stand up a docs-as-code site. It must cover three of the four Diátaxis modes: at least one tutorial, one how-to guide, and reference docs, each kept ruthlessly separate. Deploy it (Pages) and link it from the README so it is discoverable.
mkdocs.yml
site_name: My Project
theme:
  name: material
nav:
  - Home: index.md
  - Tutorial: tutorial.md
  - How-to: how-to.md
  - Reference: reference.md
Definition of done
  • Site builds with mkdocs serve and deploys to a public URL.
  • Contains a tutorial, a how-to, and reference docs (kept distinct).
  • README links to the live docs site.

Write My First ADR

Pending
Format: Michael Nygard's template (adr.github.io), committed as docs/adr/0001-....md.
Plan
To do Capture the why behind a real technical decision in one of my projects (it can be a past one) as an Architecture Decision Record. ADRs are append-only: when a decision changes, I write a new one that supersedes the old, so the reasoning survives after the decision is forgotten.
docs/adr/0001-example.md
# 0001. Title of the decision

## Status
Accepted, 2026-06-20.

## Context
What forces are at play, what constraints we have.

## Decision
What we will do.

## Consequences
+ What gets better.
- What gets harder.
Definition of done
  • One ADR committed under docs/adr/, numbered 0001.
  • Uses Status / Context / Decision / Consequences.
  • Records the reasoning, not just the outcome.

Add Vale to a Repo + CI

Pending
Tool: Vale with the Microsoft style, wired into the same CI pipeline from Week 5.
Plan
To do Add Vale (a linter for prose, what ESLint is to code) to one repo, run it over the docs, and fix what it flags. Then add it to CI so style violations fail the build, not a reviewer's patience. The first run will be noisy, that is the point.
vale docs/
$ vale docs/
 docs/install.md
  12:5  error    Did you really mean 'simply'?   Microsoft.Adverbs
  18:3  warning  Use active voice ...            Microsoft.Passive
Definition of done
  • .vale.ini configured with the Microsoft style; findings fixed.
  • A Vale step added to the repo's CI so it fails on violations.
  • CI green after the fixes land.

Soft Skill, Empathy for the Reader

Pending
The principle is theory of mind: the reader does not have the context I have. Every word that needs context they lack is a place they bounce.
Three exercises to practice this week
  • Name the audience. Say who each page is for at the top ("for developers who already have Node 20+"). The reader self-selects.
  • Read as a stranger. Open the page in a private tab, pretend I have never seen the project, and follow it. The first place I get stuck is the place to fix.
  • Watch someone use the docs. Sit a friend down, give no help, ask them to follow the tutorial. 20 minutes of usability testing beats a week of solo editing.
