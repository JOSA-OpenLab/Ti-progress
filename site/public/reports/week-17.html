Three Settings, Two Names

In Review
Open: betaflight#15891 · two lines · the same kind of bug as Week 15's #15814, a menu table that fell behind its enum.
Choosing the target
Week 15's fix was a menu that read one step past the end of a table. That kind of bug comes from a habit, not a one-off slip: someone adds an option to an enum and forgets the menu that lists it. So I looked for other goggles-menu tables that had fallen behind.

First I went through every open Betaflight issue, so I would not duplicate anyone. Most of the small ones already had a pull request, one maintainer had already fixed another locally, and the rest needed a design decision from a maintainer. So the target came from my own shortlist, re-checked against the latest master the same day.
The bug
The OSD timers can count in seconds, hundredths or tenths. Tenths was added in 2019 by #8290, which updated the timer code and its test but not the goggles menu. The menu's name table still had two names while the menu allowed three values.

So a pilot who picks Tenth in the configurator and then opens the OSD menu's TIMERS page makes the firmware read a third name that does not exist, and draw whatever pointer sits next in memory. On an F405 that is a pointer to an unrelated RC-preview variable. It has been in every release since 4.1.
Two mistakes testing caught
Betaflight's SITL build, which I used in earlier weeks, compiles the OSD menus out entirely, so a SITL test would have proved nothing. I switched to real ARM builds.

My first unit test also failed for the wrong reason: the menu kept its state between runs, so the second and third runs never re-read the setting. I fixed the test, not the firmware, and only trusted the result once each run showed the value it was given.
The proof
The fix is two lines: the missing name, plus a compile-time size check, using the same pattern the firmware already uses elsewhere, so a future option cannot be added without its name.

An Old Fix Lands

Merged
Merged: betaflight-tx-lua-scripts#548 · approved and merged by haslinghuis on 22 Oct 2026, five weeks after opening.
Why it matters
This was Week 12's fix to the Lua scripts that run on a pilot's radio. The Receiver page read RC Smoothing from a byte the firmware ignores, so on every Betaflight 4.3+ quad since 2021 the radio showed the wrong state and saving did nothing. It was proved without a radio or a quad, by running the real firmware as SITL and the real radio firmware in a browser. That repo merges slowly, so the five-week wait was expected, and the fix went in unchanged.
