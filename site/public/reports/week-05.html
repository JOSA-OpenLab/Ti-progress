The Standard

The unifying principle: write the cheapest test that meaningfully exercises the behavior. A pure function gets a unit test. A function that talks to a database gets an integration test against a real (test) database, not a mocked one. A user-facing flow gets one happy-path E2E test.
Test Pyramid & Testing Trophy
  • Pyramid (Cohn). Many fast unit tests at the bottom, fewer integration tests, very few slow E2E tests on top. The geometry is a cost model: a unit test runs in milliseconds; an E2E test can take minutes.
  • Trophy (Dodds). For modern frontend, lean on integration tests for the highest confidence per dollar, on a base of static analysis (TypeScript, ESLint).
Anatomy of a Good Unit Test
  • Arrange / Act / Assert. One logical assertion per test, so a failure points at one thing.
  • Name the behavior, not the function. test_parser_handles_trailing_comma, not test_parse.
  • Deterministic. No unseeded randomness, no real now() (inject a clock), no real network (inject a transport).
  • Fakes > mocks. Mock external services you don't own (Stripe, SendGrid); don't mock your own database, run a real one in CI.

Build a Real CI Workflow

Done
Repo: Ti-03/MacDirStat  ·  PR: #8  ·  matrix · caching · status badge.
The workflow I shipped
.github/workflows/ci.yml
name: CI
on:
  push: { branches: [main] }
  pull_request:
jobs:
  build-test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [macos-15, macos-26]   # Xcode 16 + Xcode 26
    steps:
      - uses: actions/checkout@v4
      - uses: actions/cache@v4   # SwiftPM .build + caches
        with: { key: ${{ matrix.os }}-spm-${{ hashFiles('Package.resolved') }} }
      - run: swift build -v   # static-analysis gate (StrictConcurrency)
      - run: swift test
Notes
A matrixed build-test job across macos-15 (Xcode 16 / Swift 6.1) and macos-26 (Xcode 26 / Swift 6.2, the real Liquid Glass shipping toolchain), on every push to main and every PR. It caches SwiftPM (keyed on Package.resolved), runs swift build -v as the static-analysis gate (Swift + StrictConcurrency is the Testing Trophy's static base), then swift test. No Linux or separate lint job on purpose: a macOS-only SwiftUI app can't build on Linux runners.
The matrix earned its keep
The first run was red despite a clean local build, a textbook "works on my machine" bug. GlassCompat calls macOS 26 Liquid Glass APIs (glassEffect) and ContentView uses macOS 15 MeshGradient, both guarded only by a runtime #available, which does nothing for compilation: the symbols simply don't exist in older SDKs. My Mac has the macOS 26 SDK so it compiled; GitHub's older runners didn't. Fix: a compile-time #if compiler(>=6.2) guard around the glass APIs, and dropping macos-14 (whose SDK lacks both symbols). Now green on both cells.

Run It Locally with act

Done
Done across two repos: one shows act's hard limit (macOS), the other is where act actually shines (Node/Linux) and caught real bugs before they reached GitHub.
MacDirStat — the macOS limit
act runs GitHub Actions in Linux Docker containers. A runs-on: macos-15 job has no equivalent: there is no macOS container image (Apple licensing forbids macOS in Docker), so it can't build a macOS SwiftUI + Sparkle app at all. For a macOS app the local-act loop is simply unavailable, verification is swift build / swift test on a real Mac plus watching Actions on push. Write-up in docs/ci-journal.md.
adcli — where act actually runs (Node/TypeScript, private repo)
To genuinely exercise act I used adcli, a private Node/TypeScript monorepo: a lint job (pnpm typecheck) and a test job (matrix Node 20/22, a Postgres 16 service container, migrations, pnpm cache, pnpm -r test). Running it locally caught two real failures before they ever reached GitHub: (1) @adcli/sdk wasn't resolvable in a clean checkout because its dist/ is gitignored (it only passed on my machine from leftover build output), fixed with a "build workspace libraries" step; and (2) tsc --noEmit flagged 4 pre-existing type errors in backend test mocks and page props.
act vs GitHub-hosted runners — the differences I hit
  • Architecture. Hosted is x86_64; my machine is arm64. The linux/amd64 emulation broke setup-node (exec: "node": not found), running native arm64 fixed it.
  • Missing psql. The catthehacker/ubuntu:act-latest image has no psql, so a psql -f migration step failed. Switched migrations to the existing pg-based migrate.mjs, portable on both.
  • Runner image. act defaults to a small image; pinned -P ubuntu-latest=catthehacker/ubuntu:act-latest to avoid the interactive size prompt.
  • Service ports. act binds the Postgres service to host 0.0.0.0:5432, a local Postgres on 5432 caused port is already allocated.
  • Windows runners. Unsupported by act (not used here).

Soft Skill, Time Management & Deep Work

Done
Discipline: testing and CI work reward uninterrupted focus. Time-box debugging sessions ("90 minutes, then re-evaluate"), and do one thing at a time, task-switching costs ~25 minutes to reload context. An OSS-relevant habit: batch code-review responses once or twice a day instead of replying to every comment as it lands.
Reflection
Resurrecting a stale test suite is exactly the work that punishes fragmentation: tracking the Sparkle / Package.swift gap, the radial-redesign test breakage, and the ByteFormatter unit bug needed sustained attention, not Slack-interrupted minutes. I time-boxed the debugging, worked one repo at a time, and batched the changes into three logical commits (tests, CI, docs) instead of committing reactively.

Weekly Journal

What I learned

  • A green-looking suite rots silently: a rect-to-radial refactor left 6 tests asserting on a deleted API and nothing flagged it until CI forced a compile.
  • SPM and the Xcode project are separate dependency graphs, import Sparkle built in Xcode but broke swift build.
  • The Swift compiler with StrictConcurrency is a real static-analysis gate, it stands in for lint on a macOS-only project.

What was hardest

  • Accepting that act fundamentally can't run a macOS job, the task became documenting a limitation rather than a local run.
  • The ByteFormatter bug hid behind KB/MB cases that rounded to 1.0; only GB exposed decimal-vs-binary.

What's blocking me

  • Nothing blocking. Open follow-up: adopt swift-format with an agreed config (~3,700 existing violations make it its own task).
